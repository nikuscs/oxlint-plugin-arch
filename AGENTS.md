# oxlint-plugin-arch

Architecture rules for Oxlint (`arch/*`), a vendored anti-slop plugin (`dillon-anti-slop/*`) and a folders-based preset that wires both. Published to npm; consumers install the package only.

## Read first

- Before code changes, read `.agents/references/architecture.md` for the tree, naming and code rules.
- When reviewing, use `.agents/references/quality-gate.md`.
- Docs: `docs/folders.md`, `docs/groups/<group>.md`, `docs/rules/<rule>.md`. README tables are generated by `bun run docs`.
- Before any release, read `.agents/references/release.md` and get explicit approval.

## Rules

- Rules stay generic and configurable: no app names, paths or exceptions. The preset may default conventions it can read from `package.json` or common folder names (`services/`, `migrations/`, `tests/kits/`); app-specific globs and policy live in the consumer's Oxlint config.
- Use Oxlint's ESTree API; add no other production parser.
- Reuse `src/utils/*.utils.ts` before writing a helper. A helper one file uses stays in that file.
- The repo lints itself with its own preset (`oxlint.config.ts`). Fix the code to pass; lint, fallow and TypeScript settings change only on the user's explicit request.
- Tests live in `tests/`, mirroring `src/`; nothing in `src/` is a test. Every rule has `tests/rules/<family>/<rule>.test.ts`: one `it.each` table of rows run through `testerRun`, nothing above the table, no mocks. `tests/rules/copy/copy-dashes.test.ts` is the exemplar.
- After a substantial set of changes, run the `review` skill in full (simplify, code, blast), fix its findings, and rerun the checks before reporting.

## Adding or changing a rule

1. Write `src/rules/<family>/<family>-<subject>.ts`; option types go in `src/types/<family>.types.ts`.
2. Write its `tests/rules/<family>/<family>-<subject>.test.ts`: passing rows, failing rows, and for fixable rules an output row, an already-fixed row and an `output: null` row.
3. Register it in `src/index.ts`, alphabetical.
4. Write `docs/rules/<rule>.md` (one sentence, ❌/✅ snippet, options table, config line), link it from its group page if a group enables it, and run `bun run docs`.
5. Add a bullet under `## Unreleased` in `CHANGELOG.md`.

## Validation

Run `bun run check`. After changing agent guidance, run `bun run agents:sync`.

Performance: `bun run bench <repo> [--config=oxlint.config.ts] [--top=25]` lints a real repo with every JS rule timed and prints the slowest rules. Run it before and after touching a rule's visitors.
