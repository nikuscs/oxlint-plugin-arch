# Architecture

## Rules for this file

1. Agents do not edit this file. Only the owner edits it, or an agent the owner allowed for that one change.
2. Code that does not match is fixed in the same change, never written down here.
3. A new file kind, folder or concept needs the owner's approval first; its line lands in the same change.
4. No history, dates or feature status.

## Tree

```text
src/
├── index.ts                         the arch plugin: every rule, imports and entries alphabetical
├── rules/<family>/<family>-<subject>.ts   one rule; helpers only it uses stay in the file
├── preset/
│   ├── preset.ts                    public entry: preset(), recipes, templates, types; scopes each group to its folders
│   ├── preset-folders.ts            resolves folders: keys, inheritance, units and the project lists groups read
│   ├── preset-recipes.ts            recipes and templates: plain group toggles
│   ├── preset.constants.ts          group defaults and order, rule lists, fixed values
│   ├── preset.utils.ts              override, scope, glob intersection and severity helpers; PresetError
│   └── groups/<group>.ts            one group: a builder returning overrides for the given settings
├── types/<topic>.types.ts           every type and interface, one file per topic
├── utils/<topic>.utils.ts           logic two or more files share
└── vendor/dillon-anti-slop/         forked upstream plugin; shared/ holds its own helpers
docs/folders.md, docs/groups/<group>.md, docs/rules/<rule>.md, docs/vendor.md, docs/plugin-only.md
examples/*.oxlint.config.ts          typechecked example configs
scripts/docs.ts                      generates the README group and rule tables
.agents/                             agent references, orchestrator configs, sync script
oxlint.config.ts                     self-lint with the repo's own preset (imports dist)
```

Families: `backend`, `boundaries`, `code`, `comments`, `copy`, `files`, `layout`, `naming`, `react`, `schemas`, `tests`, `types`.

## Naming

| Thing | Pattern | Example |
| --- | --- | --- |
| Rule ID | `<family>-<subject>` | `layout-object` |
| Rule file | `src/rules/<family>/<rule-id>.ts` | `src/rules/layout/layout-object.ts` |
| Rule export | camelCase of the ID, the file's only export | `layoutObject` |
| Selector rule | `astSelectorRule(selector, message)` | `codeSwitch` |
| Group builder | `<group>Group` in `src/preset/groups/<group>.ts` | `reactGroup` |
| Util export | file topic + verb or noun | `astModuleName`, `optionsPatterns` |
| Type | PascalCase starting with the file topic | `LayoutObjectOptions` |
| Constant | camelCase starting with the file topic | `presetExtensions` |

## Code

- No comments; the only exception is `oxlint-disable-next-line <rule> -- <reason>`.
- A function used once is inlined unless that breaks a lint limit (complexity 32, 400 lines).
- Autofixes change only whitespace or remove comments; anything unproven reports without a fix.
- Rules are generic: library names appear only as documented default option values.
- Option changes stay backward compatible unless the change is a declared breaking release.
